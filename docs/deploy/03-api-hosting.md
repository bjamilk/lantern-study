# Step 3: Deploy the API

Host the Lantern Study API (`apps/api-server`) on Render using the repo Dockerfile.

## What gets deployed

| Item | Value |
|------|--------|
| Service | `@lantern/api-server` (Express, port **3001**) |
| Health check | `GET /health` |
| Docker | `apps/api-server/Dockerfile` (monorepo root context) |
| Blueprint | `render.yaml` at repo root |

---

## Option A — Render Blueprint (recommended)

1. Push this repo to GitHub (`bjamilk/lantern-study`).
2. Open [Render Dashboard → Blueprints](https://dashboard.render.com/blueprints).
3. **New Blueprint Instance** → connect `bjamilk/lantern-study`.
4. Render reads `render.yaml` and creates **lantern-study-api**.
5. When prompted, set these **secret** env vars (Dashboard → Service → Environment):

| Variable | Value |
|----------|--------|
| `SUPABASE_URL` | `https://tiizkjhbrnaibaagmurl.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | From [Supabase → Settings → API](https://supabase.com/dashboard/project/tiizkjhbrnaibaagmurl/settings/api) (**secret** key only) |
| `GROQ_API_KEY` | Your Groq key (AI features) |
| `JWT_SECRET` | Auto-generated by Render if you use the blueprint, or any long random string |

6. Deploy. When live, copy the service URL (e.g. `https://lantern-study-api.onrender.com`).

### After deploy — update local env

**Root `.env`:**

```env
VITE_API_URL=https://YOUR-RENDER-URL.onrender.com
```

**`apps/mobile/.env` (or EAS secrets):**

```env
EXPO_PUBLIC_API_URL=https://YOUR-RENDER-URL.onrender.com
```

**Supabase Auth redirect URLs** — add your future web URL; keep `http://localhost:5173/**` for dev.

**API CORS** — set on Render:

```env
FRONTEND_URL=https://YOUR-WEB-DOMAIN
```

(Until the web app is deployed, `http://localhost:5173` is fine for local testing.)

## Option B — Manual Render Web Service

1. [New → Web Service](https://dashboard.render.com/create) → connect GitHub repo.
2. **Language:** Docker  
3. **Dockerfile path:** `apps/api-server/Dockerfile`  
4. **Root directory:** `.` (repo root)  
5. **Health check path:** `/health`  
6. Add the same env vars as in Option A.

---

## Verify deployment

```powershell
curl https://YOUR-RENDER-URL.onrender.com/health
```

Expected:

```json
{"status":"ok","timestamp":"...","uptime":...}
```

Optional deep check (requires `OPERATIONAL_ACCESS_TOKEN` if set in production):

```powershell
curl -H "X-Operational-Token: YOUR_TOKEN" https://YOUR-RENDER-URL.onrender.com/ready
```

## Local Docker smoke test (before cloud)

From repo root:

```powershell
docker build -f apps/api-server/Dockerfile -t lantern-api:local .
docker run --rm -p 3001:3001 `
  -e NODE_ENV=production `
  -e JWT_SECRET=local-test-jwt-secret-min-32-chars `
  -e SUPABASE_URL=https://tiizkjhbrnaibaagmurl.supabase.co `
  -e SUPABASE_SERVICE_ROLE_KEY=your_secret_key `
  -e FRONTEND_URL=http://localhost:5173 `
  -e GROQ_API_KEY=your_groq_key `
  lantern-api:local
```

Then: `curl http://localhost:3001/health`

## Production notes

- **Free Render** services spin down after inactivity; first request may take ~30s.
- Set `REDIS_ENABLED=true` and `REDIS_URL` (e.g. Upstash) when you scale to multiple instances.
- Never put `SUPABASE_SERVICE_ROLE_KEY` in web/mobile env — API server only.
- Rotate keys if a secret was ever pasted into a client env var.
